- (direction) input is INTENT.md (Epic 1: triage data and schema), read alongside seed/tickets.csv, seed/customers.csv and mcp/triage_server.py for grounding on exact column/table names
- (capability) CAP-1 a person can run uv run python load_seed.py to load seed/tickets.csv and seed/customers.csv into a local SQLite file app.db, as tables tickets and customers with the same columns as the CSVs; success: app.db exists with tickets(ticket_id, customer_id, created_at, text) and customers(customer_id, name, plan, open_tickets) matching the CSV rows, and running the command twice leaves the database unchanged (idempotent)
- (capability) CAP-2 every triage decision is validated against a schema: category in {billing, bug, access, performance, how-to}, priority in {P1, P2, P3, P4}, route in {billing-team, bug-team, access-team, performance-team, how-to-team}, and a one-sentence rationale; anything else is rejected with a clear error; success: a well-formed decision object validates, and a malformed one (missing field, wrong enum value, extra/renamed field) raises a clear, specific error rather than silently passing or crashing opaquely
- (constraint) Python 3.12 or newer, managed with uv; packages added with uv add, never pip
- (constraint) seed/tickets.csv and seed/customers.csv are read-only; load_seed.py only reads them, never writes
- (constraint) no network calls and no API keys in this epic
- (constraint) mcp/triage_server.py already reads app.db at {project-root}/app.db via sqlite3, querying tickets(ticket_id, customer_id, created_at, text) and customers(customer_id, name, plan, open_tickets); load_seed.py must produce exactly these table and column names since triage_server.py is read-only and cannot be adjusted to match
- (non-goal) the agent, the MCP tools beyond staying compatible with the existing triage_server.py, evals, and any user interface are out of scope for this epic
- (question) should the schema enforce that route corresponds to category (e.g. category=billing implies route=billing-team), or are the two enums validated independently? INTENT.md lists both value sets but never states the pairing rule

- (event) self-validate pass 2 (preservation): every done-when, must-not-change and out-of-scope line from INTENT.md traced into a capability, constraint or non-goal; no wrapper-only content dropped
